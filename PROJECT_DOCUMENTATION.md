# JobAI — AI Agentic SaaS / AI Automation Platform
*Powered by CodeByTushu*

---

## 1. Project Vision
Job hunting in the modern era is fragmented, exhausting, and repetitive. Job seekers spend countless hours manually searching across disparate job boards, parsing confusing role descriptions, customizing resumes by hand, writing bespoke cover letters, and tracking applications across ad-hoc spreadsheets.

**JobAI** is conceived as **“Your AI Career Copilot”** — an intelligent, agentic career automation platform that elevates job seekers from manual data entry to autonomous, assisted career growth. It reimagines the job hunt as a smart, organized pipeline: discovering high-fit opportunities, matching deep profile competencies against real-world job requirements, optimizing resumes for Applicant Tracking Systems (ATS), auto-drafting high-converting application assets, and tracking application lifecycles with predictive career analytics.

---

## 2. Product Goals
- **Intelligent Job Discovery**: Aggregate and surface high-match career opportunities tailored to individual candidate profiles.
- **Deep ATS & Profile Matching**: Provide transparent, metric-driven analysis of candidate resumes against real job descriptions with actionable gap analysis.
- **Agentic Career Automation**: Establish a supervised AI workflow (Job Discovery → Job Analysis → Profile Matching → Resume Analysis → Application Preparation → User Review → Application Tracking) to eliminate repetitive friction.
- **Production-Ready Portfolio & SaaS Benchmark**: Built with clean modern architecture, responsive design tokens, and modular components ready for live deployment on GitHub and Netlify.

---

## 3. Target Users
- **Active Job Seekers**: Professionals seeking software engineering, design, product, and AI roles who need faster matching and ATS-optimized applications.
- **Career Changers & Transitioners**: Candidates bridging skill transitions needing clear skill-gap intelligence and tailored resumes.
- **High-Volume Tech Applicants**: Developers and engineers who want an automated, unified copilot for tracking multi-company pipelines.
- **Recruiters & Hiring Managers**: (Future persona) Seeking candidates verified through automated capability and skill matching.

## 7. Data Flow
The platform is architected around an asynchronous, human-in-the-loop AI processing pipeline:

```

        │
        ▼
[Frontend UI (React + Tailwind)]
        │
        ├── Client-Side Multi-Parameter Filtering & Sorting
        ├── Local Demo Persistence (Saved Opportunities & Bookmarks)
        ├── Dynamic Deep-Dive AI Match Telemetry Rendering
        │
        ▼
[API Gateway / Backend Server (Planned)]
        │
        ├── Session / Demo Auth Verification
        │
        ▼
[Database / Storage Layer (Planned)]
        │   └── Profiles, Saved Jobs, Resumes, Applications
        │
        ▼

```

## 8. AI Agent Architecture
The target AI architecture operates on a multi-stage sequential agent pipeline:

1. **Job Discovery Agent**: Scans target boards, company career portals, and feeds according to user criteria.
2. **Job Analysis Agent**: Deconstructs job descriptions into required skills, preferred competencies, company tech stack, and hidden keywords.
3. **Profile Matching Agent**: Evaluates user profile vector embeddings against extracted job vectors to calculate multi-factor match percentages.
4. **Resume Analysis & Optimization Agent**: Conducts ATS diagnostic scoring, identifying critical missing keywords and impact metrics.
5. **Application Preparation Agent**: Synthesizes custom-tailored cover letters, targeted resume summaries, and tailored responses to employer questions.
6. **User Review Gate**: **(Crucial)** Always presents drafted assets to the candidate for inspection, editing, and approval before submission.
7. **Application Tracking Agent**: Updates status logs, calendars follow-ups, and monitors communication queues.

*Current Stage: The agent workflow is interactively visualised and simulated in the UI to illustrate the product concept. No autonomous background functionality is claimed until actually built.*

## 9. Authentication Strategy (Demo Mode)

### Important Demo Login Rule:
- The **Email** field is mandatory and validates basic email formatting.
- The **Password** field is required visually (to maintain standard SaaS UX expectations).
- The **Password can be ANY value** for demo access.
- **Do NOT implement real password verification at this stage.**
- **Do NOT store real passwords.**
- The demo facilitates immediate, friction-free login whenever a valid email syntax and non-empty password are submitted.
- Clearly structured code so real authentication can be added later (e.g. Supabase, Clerk, NextAuth).
- **Never describe this demo authentication as production-secure authentication.**

Sign Up similarly exists as a demonstration onboarding flow with immediate feedback and active session state.

### Screen #15: Authentication & Access System Implementation Summary
- **1. Purpose & Goals**: Deliver a modern, distraction-free authentication experience for JobAI. Supports dedicated `/login`, `/signup`, and `/forgot-password` routes, centralized demo session persistence, route protection for private career workspaces, guest-only redirection, intended redirect restoration, profile synchronization with Screen #12, and seamless demo testing.
- **2. Authentication Architecture**: Decoupled service layer (`src/services/authService.ts`) providing standard auth lifecycle abstractions (`login`, `signup`, `logout`, `getCurrentUser`, `getSession`, `restoreSession`, `isAuthenticated`, `updateUser`, `resetPasswordDemo`). Easily replaceable with Supabase Auth, Clerk, NextAuth, or Firebase Auth.
- **3. Login Flow (`/login`)**:
  - Validates required email format.
  - Accepts any non-empty password in demo mode.
  - Pre-seeded with 1-click **"Use Demo Account"** button (`demo@jobai.app` / `Alex Morgan`).
  - Creates demo session token (`jobai_demo_tok_...`) with 7-day expiration.
  - Automatically forwards user to their previously requested protected screen or `/ai-matching`.
- **4. Signup Flow (`/signup`)**:
  - Validates Full Name, Email, Password, and Password Confirmation matching.
  - Accepts any non-empty password for demo registration.
  - Creates new demo user entity in the local directory (`jobai_auth_users_directory`).
  - Immediately initializes candidate profile with user's name and email.
  - Automatically redirects to the authenticated workspace.
- **5. Logout Flow**:
  - Clears `jobai_auth_user` and `jobai_auth_session` from local storage.
  - Resets active session state and redirects to `/login`.
  - Preserves user records in demo directory so registered accounts can be re-accessed.
- **6. Demo Authentication Behavior**:
  - **Mandatory**: Email is strictly validated for format.
  - **Permissive**: Any non-empty password string is accepted.
  - Transparent demo notice banners on all forms explaining that no real credentials or passwords are saved.
- **7. Session Persistence**:
  - Stored in browser `localStorage` under `jobai_auth_user` and `jobai_auth_session`.
  - Restored synchronously during React state initialization, preventing screen flashing or unauthorized access glitching.
- **8. Auth State Management**:
  - Centralized in `App.tsx` and exposed via `currentUser`, `handleAuthSuccess`, `handleLogout`, and `handleNavigateScreen`.
  - Shared seamlessly between desktop `Navbar`, mobile drawer, `MobileBottomNav`, and `DemoAuthModal`.
- **9. Protected Routes**:
  - Private workspaces: `/ai-matching`, `/resume`, `/resume-analysis`, `/resume-builder`, `/ai-auto-apply`, `/applications`, `/ai-cover-letter`, `/career-insights`, `/profile`.
  - Guarded by `handleNavigateScreen` which intercepts unauthenticated navigation attempts, saves the target in `pendingRedirect`, triggers an informative toast, and redirects to `/login`.
- **10. Guest-Only Routes**:
  - Public routes: `/home`, `/jobs`, `/job-details`, `/pricing`, `/mobile-preview`.
  - Auth routes (`/login`, `/signup`, `/forgot-password`): When visited by an already authenticated user, displays an Active Session card with one-click navigation to their workspace and a Sign Out option.
- **11. Redirect Handling**:
  - Preserves intended destination through `pendingRedirect`.
  - Example: A guest attempting to visit `/applications` is redirected to `/login`, and upon signing in is immediately transported to `/applications`.

## 14. Known Limitations
- **Demo Mode Authentication**: Password verification is simulated for frictionless demonstration access. No credential persistence or cryptographic sessions exist yet.
- **Demo Application Submissions & Truthfulness Rule**: In accordance with user trust and API compliance, no external third-party ATS platforms (e.g., Workday, Greenhouse, Lever) are automated or spammed. All submissions operate in safe demo mode (`JOBAI-APP-XXXX` codes tracked in browser localStorage), and require explicit user review & approval before recording.
- **Demo Resume Parsing**: Resume parsing is executed through a realistic multi-stage client-side simulation (`resumeParserService.ts`) with real MIME and file size validation. No live Python OCR / Document AI backend is deployed at this stage, but the service architecture is decoupled for drop-in API integration.
- **Demo Resume Analysis**: Resume analysis operates through deterministic heuristic scoring (`resumeAnalysisService.ts`) auditing ATS criteria, keyword density, section scores, and target role compatibility. All ATS checks and keyword reviews are clearly labeled as **JobAI demo analysis** without vendor pass guarantees. The service architecture is fully decoupled for drop-in LLM / Document AI integration.
- **Demo Matching Logic**: Current AI matching uses deterministic heuristic scoring based on candidate profile evaluation and job requirement weights (`matchingService.ts`). No live LLM or continuous background processing is connected at this stage, but the service architecture is decoupled for seamless API replacement.
- **Simulated Job Results**: Job search, details, and recommendations operate against structured demo dataset rather than live web scrapers or third-party job board APIs.
- **Visualized Agent Workflows**: The multi-stage AI copilot and agent telemetry represent the architectural workflow and product prototype; autonomous background task runners will be integrated in future phases.
